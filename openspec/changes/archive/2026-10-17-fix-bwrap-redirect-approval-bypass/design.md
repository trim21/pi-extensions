# Design

## Context

`parseBashCommands` 用 tree-sitter 解析命令，`fileRedirectWritesToFile` 通过 `file_redirect` 的子节点类型判断是否写文件。tree-sitter 把重定向操作符作为匿名子节点暴露：`>`、`>>`、`>|`、`&>`、`&>>`、`>&`、`>&-`、`<&` 等。其中 `>&` 同时承担两种语义，取决于右操作数：fd 号或 `-` 时是复制/关闭 fd，否则是 `&>file` 的别名（写文件）。现有实现把 `>&` 整体归入 fd 复制，导致漏判。

## Goals / Non-Goals

**Goals:**

- 按 tree-sitter 给出的右操作数节点区分 `>&` 的两种语义，堵住 `>& file` 的自动放行路径。
- 静态无法确定右操作数时保守交人审，不引入新的放行面。
- 保持 `2>&1`、`>&2`、`>&-` 等纯 fd 操作仍可命中 allow 规则自动放行。

**Non-Goals:**

- 不改变 `>` / `>>` / `>|` / `&>` / `&>>` / `<>` 的既有判定。
- 不引入 shell 展开或运行期求值；`>&$fd` 不尝试解析变量内容。
- 不调整审批规则匹配、持久化或 UI。

## Decisions

### 以右操作数节点类型判定，而不是解析操作符文本

tree-sitter 的 `file_redirect` 已经把操作符与右操作数拆成兄弟节点（`>&` + `destination`），直接看 destination 即可。判定规则：`destination.type === "number"` 或 `destination.text === "-"` 时为 fd 复制/关闭，其余一律视为写文件。

备选方案是正则匹配整个 `file_redirect.text`，但需要自己处理引号、空白、转义与多重重定向，容易再次漏判；tree-sitter 的节点边界是现成的。

### 目标不明确时保守视为写文件

`>&$fd` 的变量可能展开为数字（fd 复制）或文件路径（写文件），静态无法确定。`2>& file` 在 bash 中本身是非法重定向（显式 fd 的右操作数必须是 fd 号），但保守视为写文件只会多弹一次确认，不会误放行。安全边界优先于少量误报。

## Risks / Trade-offs

- [把 `2>& file` 这类非法命令交人审会多一次确认] → 该命令本身会失败，正常脚本不会使用；相比漏放行写文件，误报成本可接受。
- [tree-sitter grammar 升级可能改变节点类型] → 判定同时接受 `number` 类型与文本 `-`；新增未知节点类型默认落入「写文件」分支，失败方向是更严格而非更宽松。

# Design

## Context

见 proposal.md - Why。实现约束来自 `@parcel/watcher` 2.6.0 的 Linux backend（其他平台后端行为需在实现时验证，但接口一致）：

- 收到目录 `IN_CREATE` / `IN_MOVED_TO` 时，backend 在 `handleSubscription` 里同步调用 `watchDir` 给该目录建 watch，之后才把事件交给 JS。因此 JS 收到目录 create 事件时，该目录上的 watch 已经就位：此前的文件写入不会有事件、但文件已在磁盘上；此后的写入一定会有事件。
- `watchDir` 只给单个目录建 watch，不递归；递归只发生在 `subscribe` 初始 `getTree` 时。所以整树 move 进来时只有顶层目录被监听，已有嵌套目录永远不会被 watch（实测：移入后写 `a/b/new.txt` 无任何事件）。
- 目录 create 的扫描与补齐只需处理“已有的”文件；watch 就位之后的变更由内核事件负责。
- 现有实现（`src/lib/lsp/watcher.ts`）的 `processEvents` 对目录事件直接丢弃，`seenDirectories` 只用于删除时判断 `isDirectory`；忽略规则由相对 root 的 glob 与绝对路径 `ignoreDirs` 组成。

## Goals / Non-Goals

**Goals:**

- 目录创建后立即写入的文件不再丢事件。
- 整树移入时补投树内已有文件，并让移入子树的后续变更持续产生事件。
- 复用现有忽略语义与去抖 / 批量 / 停用链路，不改变对外的事件类型映射。

**Non-Goals:**

- 不做事件去重（重复 `created` 对 LSP 客户端无害）。
- 不改变忽略规则、配置结构或轮询降级语义。
- 不跟随符号链接指向的目录（与 parcel 现有行为一致）。
- 不为已经被轮询降级接管的事件源补扫。

## Decisions

### 目录 create 时递归扫描并补投文件

`processEvents` 区分“事件目标是不是目录”：目录的 created 事件不再直接丢弃，而是触发一次递归扫描。

- 扫描用一个独立的 `readdir(..., { withFileTypes: true })` 递归实现，目录加入 `seenDirectories`，文件通过现有 `push()` 走同一套去抖 / 批量 / 截断逻辑。
- 扫描前先按 `isIgnored` 判断该目录本身；每个子项同样先判忽略，命中内置 glob、配置 `ignore` 或绝对路径 `ignoreDirs` 的子树不进入、不投递，语义与事件层保持一致。
- 扫描失败（目录已被删除、权限问题）按无内容处理，不报错。

替代方案：用 `getEventsSince` 快照对比补事件——需要维护额外快照并会把整个 root 的变更重复上报，代价远大于一次 `readdir`。

### 为含子目录的新建目录补挂子订阅

扫描 / 探测到新建目录内已有子目录时，对它调用 `subscribe()` 建立一个递归子订阅，事件回调复用同一个 `handleEvents`：

- 选“有子目录才订阅”而不是“所有新建目录都订阅”：顶层目录自身的 watch 已覆盖直接子项，唯一缺口是已有嵌套目录；普通 `mkdir`（空目录）与 `mkdir + 立即写文件` 不产生子订阅。`mkdir -p a/b` 会多建一个以 `a` 为根的子订阅，属于可接受的误触发。
- 顺序为：先 `readdir` 顶层判断是否有子目录 → 有则 `subscribe` → 再递归扫描。这样扫描在子订阅建立之后执行：扫描前写入的文件被扫到，扫描期间写入的文件由新 watch 出事件，不会落在两者之间的空窗。
- 已存在子订阅根之下的新目录不再重复订阅（避免嵌套订阅）；但仍要扫描它以补齐“新建目录立即写入”的文件。
- 该目录被删除（路径等于或位于某个子订阅根之下）时退订并移除记录；`stop()` 时退订全部子订阅。退订失败按现有 `stop()` 的方式忽略。
- 订阅失败若为 `ENOENT` / `ENOTDIR`（目录在订阅前已被删除）静默跳过；其他错误走现有 `handleError`（资源耗尽仍按现有逻辑降级轮询）。
- 轮询降级生效后不再建立子订阅（快照对比已覆盖范围）。

替代方案：收到目录 create 后重建整个 root 订阅——`getTree` 会全量扫描工作区，目录创建在构建期间很频繁，代价不可接受，且重建窗口会丢事件。

### 生命周期与已知重复

父订阅与子订阅会共享同一 wd：子订阅根下第一层的事件双方都能看到；移入后新建的目录还会被父订阅顺着事件纳入自己的 watch，因此这些路径的后续事件也会重复投递。重复对 LSP 客户端无害，是 spec 显式允许的取舍。`seenDirectories` 由扫描补齐，移入子树内的目录被删除时仍能正确标记 `isDirectory: true`。

## Risks / Trade-offs

- [每次目录创建多一次 `readdir`] → 被忽略目录不扫描；普通目录扫描只读元数据，构建场景的事件量仍由既有去抖与批量上限约束。
- [`mkdir -p` 触发不必要的子订阅，长期累积] → 只在“已含子目录”时订阅，且子目录删除时退订；`node_modules`、`dist` 等构建目录命中忽略，不会累积。
- [子订阅与父订阅事件重复] → spec 允许重复；不实现跨订阅去重，避免引入跨批次状态。
- [非 Linux 后端行为未实测] → 实现时在受支持平台验证；扫描逻辑不依赖 inotify，子订阅使用 parcel 公共 API。
- [扫描大目录产生大量事件] → 进入现有 `maxBatch` 截断并只提示一次，行为与内核事件洪峰一致。
